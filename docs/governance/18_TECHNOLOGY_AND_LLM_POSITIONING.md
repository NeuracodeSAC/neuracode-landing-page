# Technology & LLM Positioning

Status: BUSINESS-POSITIONING BASELINE
Date: 2026-08-16

## Why this exists
Executive buyers increasingly arrive with a named technology in mind:
“Claude”, “OpenAI”, “Codex”, “Bedrock”, “agents”, etc.

Neuracode should capture that demand without becoming a reseller-style tool page or implying that every problem needs an LLM.

The website therefore follows two layers:

1. **Outcome/capability first**
   - automate a process;
   - analyze/report;
   - integrate systems;
   - design an agentic workflow;
   - improve SDLC/AI adoption;
   - govern and operate the solution.

2. **Technology evidence second**
   - show the ecosystems Jack/Neuracode can evaluate and implement;
   - explain why the final choice depends on the problem.

## Core public message
Preferred wording:

> Trabajamos con múltiples ecosistemas de IA y LLMs. Seleccionamos modelo, proveedor y arquitectura según el proceso, los datos, la integración, la seguridad, el costo y la operación.

Alternative:

> No vendemos un modelo específico. Podemos trabajar con distintos LLMs y plataformas y elegir la combinación adecuada para cada caso.

Avoid absolute wording such as:
- “dominamos todos los LLMs”;
- “cualquier LLM” as an unqualified universal claim;
- “somos partners de…” without evidence;
- “Claude es siempre mejor”;
- “todo proceso necesita agentes”.

## Governed taxonomy
Do not collapse everything into “LLMs”.

### LLM / model-provider ecosystems
Visible examples based on user-confirmed working context:
- **Anthropic / Claude**
- **OpenAI**

These may be named in executive-facing copy when relevant.

### Developer/agent products
- **Codex** — surface as an OpenAI developer/agent ecosystem capability, not as a separate base LLM claim.

### Model access / enterprise AI platforms
- **AWS Bedrock** — describe as a managed platform/service for accessing and operating foundation-model capabilities; do not call Bedrock itself “an LLM”.

### Agentic / orchestration frameworks
- **LangChain**
- **LangGraph**

These are frameworks/orchestration tools, not LLMs.

### Protocols / integration patterns
- **MCP**
- tool use / function calling
- skills
- structured workflows

### Architecture patterns
- RAG when justified
- deterministic workflow
- LLM-enabled workflow
- single agent
- agentic workflow
- multi-agent only when complexity justifies it
- human-in-the-loop
- evaluations / observability / guardrails

## Evidence state
User has explicitly stated practical familiarity/experience with:
- Claude;
- Codex / OpenAI ecosystem;
- AWS Bedrock;
- pre-current-wave AI agents;
- current agentic systems;
- LangChain;
- LangGraph;
- agentic workflows;
- skills and tool-oriented patterns.

Do not infer:
- official vendor partnership;
- every vendor certification;
- every model family;
- production experience with a technology not specifically evidenced;
- “expert in all LLMs”.

- MCP

### `/empresas`
Add a buyer-oriented block:
**¿Ya tienes una tecnología definida?**

Copy:
> Podemos partir de un proceso o de una plataforma ya elegida. Si tu organización está evaluando Claude, OpenAI/Codex, AWS Bedrock u otro ecosistema, revisamos integración, seguridad, datos, costo, operación y criterios de evaluación antes de escalar.

Add FAQ:
**¿Trabajan con Claude, OpenAI o AWS Bedrock?**
Answer:
> Sí, podemos trabajar con distintos ecosistemas. La recomendación final depende del caso de uso, arquitectura existente, datos, seguridad, costo y operación. Cuando la mejor solución no requiere un LLM, también lo decimos.

This is intentional commercial/SEO language for executive buyers searching by technology name.

### `/jack-aguilar`
Show technical judgment, not a badge wall.

Suggested structure:
**Ecosistemas y patrones con los que trabajo**
- Models/providers: Anthropic/Claude, OpenAI
- Platforms: AWS Bedrock
- Agentic engineering: LangChain, LangGraph, MCP, skills, tools
- Patterns: RAG, agentic workflows, HITL, evaluations
- Software/data: Python, .NET, APIs, cloud, distributed systems, BI/ML

Credentials are separate from hands-on ecosystem experience.

### `/casos`
Technology tags belong to the specific case only if used/evidenced.
Do not retroactively add Claude/LangGraph/Bedrock to historical work.

### `/academy`
Vendor-specific workshop/course language is allowed only when an actual offering exists.
Do not maintain a permanent “Claude course” or similar claim solely for SEO.

## Vendor logo policy
Default: use text chips/names.

If vendor logos are used:
- verify official current brand assets and usage rules at implementation time;
- never call the section “Partners” unless partnership is documented;
- do not visually make vendor logos larger/more prominent than Neuracode;
- do not recolor/distort vendor marks;
- preserve neutral wording: “ecosistemas”, “tecnologías”, “herramientas”.

## SEO intent without keyword stuffing
Useful phrases, where naturally relevant:
- automatización con IA;
- automatización con LLMs;
- agentes de IA para empresas;
- Claude para procesos empresariales;
- OpenAI para automatización;
- AWS Bedrock para soluciones empresariales;
- agentic workflows;
- AI / Agentic SDLC.

Do not create thin provider landing pages yet.
Only create provider-specific pages when:
- real demand/search data exists;
- there is enough original technical/commercial content;
- the page answers a distinct buyer need.

## Sales principle
Named technology creates the conversation.
Judgment closes the architecture.

A lead may ask for Claude.
The website should make clear that Jack/Neuracode can:
1. understand the process;
2. validate whether LLM/agentic AI is justified;
3. choose architecture/provider;
4. implement;
5. evaluate;
6. govern/operate.

That is the differentiator.
